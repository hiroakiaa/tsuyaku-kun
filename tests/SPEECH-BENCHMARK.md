# 音声認識の比較手順

1. speech-benchmark.json の30例を、同じ話者・同じ端末と回線で読む。可能なら同じ音声を繰り返して使う。共有先へ録音をアップロードする必要はない。
2. 出力された日本語を recognized に、話し終わりから表示までの時間を speechToDisplayMs に記入する。空欄は未計測のままにする。
3. node tools/evaluate-speech.mjs tests/speech-benchmark.json を実行する。数字の誤り、文字誤り率、未計測数を確認する。意味、否定、専門用語、訳の自然さは人が確認する。
4. 声の大きさ・周囲の音・言語・端末・回線を記録し、変更前後で条件をそろえる。

今回の変更：20msの平均音量で区切りを判定し、短い返事は120ms以上、無音は600ms、処理する音声は最大4秒。前の200msを保持する。処理上の分割と発話末尾を区別し、日付・曜日・未完の前置きは続きの発話と結合する。最初の認識結果は続きの認識を待たず翻訳・表示し、続きは同じ字幕IDの新しい版として更新する。1枚につき2音声区間まで結合し、続きがなければ本文を再翻訳せず完了表示にする。音声が欠けた場合は前後を結合しない。実端末での精度・速さの改善率は未計測。firstDisplayLatencies / p95FirstDisplayMs は発話開始から最初の訳の表示までの推定時間。speechLatencies は発話末尾基準で別の計測。

Cloudflare公式モデル仕様: https://developers.cloudflare.com/ai/models/%40cf/openai/whisper-large-v3-turbo/

## 無言中の環境音の確認

音声検出（vad_filter）と無音中の幻覚抑制を有効にした。認識結果に無音確率・低確信度と高圧縮率の根拠がある区間を除外し、前後の正常な区間を残す。繰り返し文字列だけでは削除しない。確信度が返らない場合は未判定として扱う。

実端末で、静かな無言30秒、換気扇など一定の環境音30秒、環境音→短い小声の「はい」→環境音、実際に「はい、はい、はい」と繰り返す発話をそれぞれ確認する。無言中の字幕数・聞き逃し・発話末尾から表示までの時間を記録する。元の環境音は提供されておらず、今回の現象を同じ音で再現した検証は未実施。

## 先行表示の確認

「10月9日、金曜日に終業式があります。下校は15時40分です。」を続けて読み、最初の訳が続きの認識を待たず表示され、同じカードに追記されることを確認する。処理上の4秒区切り・600msの間・10秒以上の間・マイク停止・話し手切替を比較する。AIが遅い場合も古い結果が新しい版を上書きしないこと、同じ本文の完了通知で翻訳回数が増えないことを確認する。先行表示と文脈を反映した訳の更新では、追加のAI翻訳費用が発生し得る。更新ごとのusageIdを費用に計上し、完了通知は同じusageIdで二重計上しない。実音声での改善率は未計測。
