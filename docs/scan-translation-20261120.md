# 2026-11-20 写真PDFの翻訳表示修復

対象コミット: 8c5b3fd。公開画面 documents.js v260 / admin document-library-279。Worker: 9aa05428-9dad-41b0-a0c8-fb2017e86e98。

## 原因と修正
- 写真資料の翻訳が非構造のtextだけになっても成功として保存・再利用され、位置合わせ側でsourceなしのTypeErrorになっていた。不完全な旧キャッシュは自動再生成し、すべてのページ翻訳をキー付きの行データとして保存する。
- 取り込み時と表示時でOCRエンジン・画像が異なり文字列がずれた。表示時も原寸画像と同じOCRを優先し、OCRだけに限定した一致率・計算量上限付きの座標復旧を追加。原文QAデータや訳文を書き換えず、通常PDFの厳密な照合は維持する。

## 実際に確認した結果
- 修正前: 添付スクリーンショット中の写真部分を非公開試験登録して同じ表示失敗を再現。sourceLines:0 / render-TypeError。試験資料は削除済み。
- 修正後の公開版: 実在の人物・学校情報を含まない架空の日本語便りJPEGを、公開管理者画面→資料QA→作成で登録。英語を選択し、再試行操作なしで画像上に英訳12ブロックを表示。1280pxの2列と390pxの1列で確認。ブラウザーエラー0件。試験資料はHTTP200で削除。API・認証・配信JSの差し替えなし。
- 既存共有資料【資料】通訳くん: 公開管理者画面→保管庫から開き、原文切替後に閉じ、保管庫の英語選択で再度開いて自動翻訳表示。390px/1280pxとも32英訳ブロック、ブラウザーエラー・資料API失敗0件。
- package.jsonのテスト21系統すべて合格。不完全キャッシュ修復・修復後の再利用を追加。通常PDFの位置合わせ・原文切替・キャッシュ再利用のブラウザー検証も両幅で合格。
- 証跡: checks/generated-scan-public.log、checks/generated-scan-translation/{result,mobile}.png、checks/library-translation-public.log、checks/library-translation/public-{390,1280}.png。ローカル証跡はコミットしない。

## 未確認・再開時の注意
- 実機iPad/iPhone Safariは接続していない。上記はChromiumブラウザーであり、390pxの縮幅確認はSafari実機確認ではない。
- 添付写真そのものの再登録は自動承認審査で拒否。個人情報の可能性と外部送信が取り消せないことが理由。ユーザーに非公開登録・確認後削除の明示確認を依頼済み。許可前は再送信しない。生成資料で安全に独立検証した。
- 公開・検証の代替手段: 既存Git認証でHEAD:mainへpush、既存Wrangler CLIでWorker更新、Playwrightの実管理者UIで認証と登録を行う。接続ブラウザーがなくてもこの経路は使用できるが、実機Safariとは区別する。認証情報は出力しない。
- 通常の既存PDFで少量のOCR差を許容しない。幾何OCR復旧は全runがocrBox付きOCRの場合だけ。
