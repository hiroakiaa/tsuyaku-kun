# 通信・表示の改善と検証（2026-10-20）

## 1〜10：優先項目

| 番号 | 対応 | 確認方法 |
|---|---|---|
| 1 | 双方向・文字入力・発言メッセージの配信試験 | `tools/live-caption-check.ps1`。実機の音声認識とは別の試験 |
| 2 | サーバー受付、相手アプリの表示確認を区別 | `caption_accepted` / `caption_received` / `caption_delivered` |
| 3 | 未送信・送信確認待ち・再試行を表示 | `CaptionDelivery` と字幕カード |
| 4 | 参加と字幕通信、WebRTC音声状態を区別 | 参加者の状態表示。音声到達・人の読了は保証しない |
| 5 | 翻訳待ちの確定原文を相手にも表示 | `caption_pending`。途中の認識文字は一覧へ追加しない |
| 6 | 同じ字幕IDで上限付き再送・保存結果の再配信 | 同一ID・版の再送と `caption_sync` はAIを再実行しない |
| 7 | 背景復帰時の受信再開と未確認送信の保持 | マイクはOFFのまま。履歴から表示を復旧 |
| 8 | offline / online と無応答を検知 | 75秒受信なしで通常の再接続へ。回線切替実機は別途 |
| 9 | 公開前の組み合わせ試験手順を固定 | 下記の実機チェック表。実機未確認を合格にしない |
| 10 | 管理画面に受付・受信・表示の経過を追加 | メモリー内200件。本文・氏名・ルームID・字幕ID・接続キーを出力しない |

翻訳完了時の配信条件を、発言者の接続継続ではなくルームの有効性に変更した。翻訳実行後に発言者が切断しても、残っている受信者へ結果を配信する。終了済みルームへは配信しない。AI開始前の期限・認証・予算制限は維持する。

「相手端末に表示済み」は相手アプリがDOMへ表示した確認で、人が読んだという意味ではない。古い版の受信アプリが確認通知に対応していない場合は表示確認待ちのままになる。

## 実機チェック表

Android Chrome→iPhone Safari、その逆、同じWi-Fi、Wi-Fiと携帯回線、回線切替、画面ロックと復帰、Bluetooth接続と切断、マイク拒否、授業の生徒参加を確認する。各組み合わせで参加者表示・文字送信・発話字幕・音声・未着通知・復帰・終了を記録する。

デスクトップの画面幅変更はスマートフォン実機試験の代わりにしない。合成した発言メッセージの配信試験もマイク認識の代わりにしない。

## 再現・公開確認

1. `npm test`
2. 公開後に `pwsh -File tools/live-caption-check.ps1`（架空の学校案内のみ）。受付・双方向配信・表示確認プロトコル・再配信時のusageId不変を確認する。
3. `pwsh -File tools/live-caption-check.ps1 -Browser` の招待URLをブラウザーで開く。相手の表示確認後、文字を送信し、再読み込み後に履歴と新しい字幕が表示されるか確認する。
4. `node tools/verify-release.mjs` と `/health` のbuildを確認する。

## 切り戻し

今回の変更前のソースは `65d0e9085841f724274f5cde34350155964059c3`。本番Workerの変更前バージョンはダッシュボードで `eb5462a4` が100%配信中だった。

通常は問題の変更コミットを `git revert <対象コミット>` で取り消してmainへ反映し、既存のGitHub PagesとCloudflare Buildsの両方を更新する。権限・シークレット・Durable Objectを削除しない。緊急時にWorkerのデプロイ履歴から直前バージョンへ戻す場合も、画面のバージョンと組み合わせを確認する。新しい確認通知を知らない旧サーバーは無視する設計だが、表示確認機能は使えなくなる。

切り戻し後も公開URL・health・文字の双方向送信を再確認する。本文やシークレットを公開ログへ貼り付けない。
