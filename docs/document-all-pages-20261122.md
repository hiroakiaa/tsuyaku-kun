# 選択言語の全ページ翻訳準備

資料を開くと、選択言語の表示ページを最優先に全ページをバックグラウンドで順次準備する。従来の選択言語の次の1ページのみという制限をなくした。英語の全ページ準備も維持。日本語は原文表示のままで英語を準備。保存済み結果は既存の資料単位・版単位・ページ単位キャッシュで再利用する。表示中の翻訳を優先し、オフライン/タブ非表示/資料を閉じた間は新規ジョブを止める。失敗は2回まで再試行し、オンライン復帰時に再開できる。

翻訳中の表示は資料内右上へ移し、z-indexを切替ボタンより上へ。読み込み中だけ切替ボタンを折り返して右上表示との重なりを避ける。完了時には表示を消す。

49組テスト合格。制御した3ページのUI検証で、ページ1のままポルトガル語1/2/3、英語1/2/3の順に要求した。390幅で翻訳中表示の右/上余白8px、切替ボタンと重なりなし、切替ボタンより上の層を確認。公開後の実測を追記する。

## 公開後の確認

公開1c83804、資料v287/CSS111/admin306、公開HTMLと265資材一致。公開資材＋制御した翻訳応答の390幅で、翻訳中表示の上/右余白8px、切替ボタンと重なりなし、z-indexが切替ボタンより上であることを確認。選択言語3ページと英語3ページを、ページ1のまま要求した。

候補差し込みなしの公開版で、ページ見出しが異なる3ページの架空スキャンPDFを共通資料へ登録。初期言語をポルトガル語にして開き、ページ1を表示したままpt1/2/3→en1/2/3が準備完了。認識3件と翻訳6件の生成成功をAPI応答で確認。別の匿名利用者でも同じ全ページを準備し、認識3件・翻訳6件すべてcache、翻訳input/output tokensすべて0。試験資料は所有者APIで削除済み。

検証スクリプトは初めにSPA遷移で実行されない初期設定を使って日本語のまま待つ誤りがあり修正。その後、同一本文ページの再利用を新規API呼出しと誤判定したため、見出しの異なるページへ変更して再確認した。これら失敗資料も削除済み。実機Safariは未確認。
