# PDFの資料内翻訳の復旧確認（2026-11-19）
- 公開実装: 3b150aa / 画面 v258 / documents.js v252。
- 原因: 保存済みの段落訳とPDFの物理行の粒度が異なると、厳密な位置照合が失敗し、資料画像を覆うテキスト専用パネルへ切り替わっていた。
- 共通修正: 元資料との文字対応を確認したうえで訳文を物理行の表示領域へ配分し直す。訳文の追加生成はしない。位置照合できない場合にテキスト専用パネルへ自動置換する処理は廃止。
- 公開配信コードの模擬PDF試験: 390px（1列）・1280px（2列）で、段落単位の保存済み訳文から資料画像上への表示、原文切替、キャッシュ再表示を確認。
- 公開版の実資料「【資料】通訳くん」: 両幅でPDF canvas保持と32か所の翻訳表示を実際のAPI応答で確認。テキスト専用パネルは0件。日本語に戻すと翻訳レイヤーが非表示になることも確認。
- 公開版での実資料確認は tools/check-document-live-layout.mjs、模擬PDF確認は LIVE_DOCUMENT_LAYOUT=1 tools/check-document-inline-translation.mjs。既存の共通資料を利用し、新規試験資料の登録・削除は行っていない。
- スマホ幅のブラウザー検証であり、物理iPhone/iPad Safariの確認ではない。全種類のPDFでの網羅試験ではない。
