## 再開手順

1. `git status --short` と `git log -1 --oneline` で作業状態を確認する。
2. `node tests/document-qa.mjs` で索引の再利用を確認する。`node tools/verify-release.mjs` で公開ファイルとAPIビルドを照合する。
3. ローカルの全テストと公開HTML・140アセット・APIビルドの照合を再実行し、すべて成功。通常の自動Chromeで外部接続が拒否された場合は、公開試験用の承認済み実行経路を使う。
4. 本番の操作試験には合成資料を使い、終了時に作成者として削除する。
5. 当初の25項目と確認結果を一件ずつ照合する。実機確認と実データ確認は、検証できる端末または認証済み環境で行う。

公開版の既存Chromeセッションで管理者の「実績」から「試験結果・公開履歴」を開き、公開版 c49f3c0e と資料QAの公開後テスト成功を確認（項目30）。Google月報のボタンを押した後は認証待ちのままで、月報本体とダウンロードは未確認。

月報と請求データは別々の管理者認証を使う。FirebaseのGoogleポップアップは毎回アカウント選択を要求する。アプリの管理者モーダルが開いていても、月報や処理別費用を取得した証拠にはならない。この確認記録は停止前のもの。現在はGoogle認証を必要とした機能を停止中。
月報APIの集計関数をメモリー内で直接実行し、先生・生徒の2端末分と生徒側の同一データ再送を検証。利用2件、字幕4件、120秒、Live費用1回分、字幕表示確認2件、再接続・復旧各1回、復旧3秒を確認。本番月報への試験記録の書き込みなし。利用可能な端末でgcloud・Firebase CLIおよびiPad操作用CLIは確認できなかった。
