# 資料QAの公開確認と再開手順

| 確認対象 | 確認結果 |
|---|---|
| 全文方式と検索方式の5問比較 | 本番で意味検索追加の前後に実測。[比較表](document-qa-benchmark.md)、[追加前の生データ](document-qa-baseline.json)、[追加後の生データ](document-qa-current-benchmark.json)を保存済み。追加後は両方式で5問正答。費用はOpenAIの生成分。 |
| 意味検索 | 本番APIで英語の質問から日本語資料の根拠を取得。初回は索引を計算、次の質問では再利用。 |
| 共通保管庫 | 公開版Chromeで合成資料2件を資料名順・新着順・期限順・最近開いた順に並べ替え。最後に開いた資料が先頭に移ることを確認し、試験資料を削除。 |
| 質問の再試行 | 公開版Chromeで共通保管庫を閲覧者として開き、初回だけHTTP 503を模擬。再試行で本番から根拠付き回答を取得し、質問の重複がないことを確認。試験資料を削除。 |
| 根拠強調・進捗・質問履歴 | 公開版Chromeで引用箇所の強調、検索から回答への進捗更新、再読み込みによる履歴復元を確認。 |
| PDF差し替え | 公開版Chromeで同じURLのまま回答が更新され、別タブを再読み込みしても旧回答が復元されないことを確認。 |
| iPadのPDF選択 | WindowsのiPad設定WebKitで公開版を操作し、登録から質問・根拠ページ表示まで確認。iPad実機では未確認。 |
| 月別費用・内訳 | 公開版の画面モジュールを試験データで検証。管理者Googleアカウントを使った実データの確認は未実施。 |

## 再開手順

1. `git status --short` と `git log -1 --oneline` で作業状態を確認する。
2. `node tests/document-qa.mjs` で索引の再利用を確認する。`node tools/verify-release.mjs` で公開ファイルとAPIビルドを照合する。
3. 本番の操作試験には合成資料を使い、終了時に作成者として削除する。
4. 当初の25項目と確認結果を一件ずつ照合する。実機確認と実データ確認は、検証できる端末または認証済み環境で行う。
